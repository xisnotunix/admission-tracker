# 🎓 Трекер поступления

Бесплатное мобильное веб-приложение для одного абитуриента из Кыргызстана: дедлайны стипендий и вузов, требования, чек-лист документов, журнал изменений и напоминания в Telegram. Минимальный агент раз в неделю (с ноября по январь — каждый день) проверяет официальные страницы и сообщает, если на них что-то изменилось.

Всё работает на бесплатных сервисах: GitHub Pages, GitHub Actions, Telegram Bot API и бесплатный тариф Gemini API или Groq. Своего сервера нет.

## Как это устроено

```
data/programs.json   ← данные программ (правите вы или workflow «Review change»)
data/sources.json    ← БЕЛЫЙ СПИСОК URL для агента
data/changelog.json  ← журнал: изменения страниц и предложения агента
data/state.json      ← служебное: хеши страниц, время проверки, ошибки
data/snapshots/      ← последний текст каждой страницы (для diff)

agent/check_sources.py    агент проверки
agent/llm.py              извлечение данных через Gemini / Groq
agent/notify_deadlines.py напоминания за 60/30/14/7/1 день
agent/review.py           подтверждение/отклонение изменений, отметки чек-листа

.github/workflows/check-sources.yml       cron: агент
.github/workflows/deadline-reminders.yml  cron: напоминания (09:00 по Бишкеку)
.github/workflows/review.yml              ручной запуск: approve / reject / checklist
.github/workflows/tests.yml               юнит-тесты агента

index.html, assets/       фронтенд (чистый HTML/JS, без сборки)
```

### Алгоритм агента

0. У источника есть тип `kind`. `page` — страница конкретной программы, на ней агент ищет дедлайн и требования. `catalog` — список конкурсов, на нём агент ищет **новые** программы (см. «Поиск новых стипендий»).
1. Берёт **только** URL из `data/sources.json` (`enabled: true`). Веб-поиск не использует, по ссылкам со страницы не ходит. Если сайт делает редирект на домен не из белого списка, проверка этого источника завершается ошибкой.
2. Скачивает страницу, вырезает скрипты, меню и подвал, получает текст и считает от него sha256.
3. **Хеш не изменился** — обновляется только `last_checked`, LLM не вызывается.
4. **Хеш изменился** — сохраняется снимок, в журнал пишется diff («добавлены/удалены строки»), в Telegram уходит уведомление. Затем текст (точнее, релевантные фрагменты, максимум 12 000 символов) отправляется в LLM с просьбой вернуть JSON: `deadline`, `opens`, `requirements` и дословную цитату для каждого поля.
5. **Защита от выдумок.** Если поля на странице нет, LLM должна вернуть `null`. Каждую цитату агент ищет в тексте страницы. Если цитата не найдена дословно (с поправкой на регистр, пробелы и типографские кавычки), поле отбрасывается.
6. Проверенные значения, которые отличаются от текущих, попадают в журнал со статусом **«требует проверки»** (`pending`). `programs.json` агент сам не меняет: он только обновляет метки `last_checked` и `last_changed`.
7. Вы подтверждаете или отклоняете изменение (см. ниже). Подтверждение — это коммит, поэтому вся история остаётся в git.

## Пошаговая настройка

### 1. Создайте репозиторий

1. На github.com нажмите **New repository**, например `admission-tracker`. Репозиторий должен быть **Public**: на бесплатном тарифе GitHub Pages работает только с публичными. В данных нет ничего секретного, а ключи хранятся в Secrets.
2. Загрузите файлы этой папки:
   ```bash
   git init -b main
   git add .
   git commit -m "Initial commit"
   git remote add origin https://github.com/<ваш-логин>/admission-tracker.git
   git push -u origin main
   ```

### 2. Включите GitHub Pages

**Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / `(root)` → Save.**
Через 1–2 минуты приложение откроется по адресу `https://<ваш-логин>.github.io/admission-tracker/`.
Откройте его на телефоне и добавьте на главный экран («Поделиться → На экран Домой» в iOS или «⋮ → Добавить на главный экран» в Android).

### 3. Разрешите Actions делать коммиты

**Settings → Actions → General → Workflow permissions → Read and write permissions → Save.**

### 4. Создайте Telegram-бота

1. В Telegram откройте **@BotFather** и отправьте `/newbot`, затем придумайте имя и username. BotFather пришлёт **токен** вида `123456:ABC…`.
2. Напишите своему боту любое сообщение, например `/start`. Без этого бот не сможет вам писать.
3. Узнайте свой chat id: откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": 123456789`. Это число и есть chat id.
4. В репозитории откройте **Settings → Secrets and variables → Actions → New repository secret** и добавьте:
   - `TELEGRAM_BOT_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — ваш chat id.

### 5. Получите бесплатный ключ LLM (достаточно одного)

| Провайдер | Где взять ключ | Секрет | Модель по умолчанию |
|---|---|---|---|
| **Gemini** (рекомендуется) | https://aistudio.google.com/apikey | `GEMINI_API_KEY` | `gemini-2.5-flash` |
| **Groq** | https://console.groq.com/keys | `GROQ_API_KEY` | `llama-3.3-70b-versatile` |

**Лимиты бесплатных тарифов** (по состоянию на октябрь 2026; их часто меняют, поэтому проверяйте актуальные цифры в консоли провайдера):
- Gemini Flash: примерно 10–15 запросов в минуту и от 100 до 1 500 запросов в день, в зависимости от модели и даты. Google несколько раз урезал бесплатный тариф, а Pro-модели убрал из него в апреле 2026. На бесплатном тарифе запросы могут использоваться для обучения моделей, но здесь отправляется только текст публичных страниц. Точные лимиты: https://ai.google.dev/gemini-api/docs/rate-limits.
- Groq `llama-3.3-70b-versatile`: примерно 30 запросов в минуту и 1 000 в день, но всего около 12 000 токенов в минуту и порядка 100 000 токенов в день. Поэтому агент отправляет не всю страницу, а фрагменты до 12 000 символов. Точные лимиты: https://console.groq.com/settings/limits.

**Сколько нужно на самом деле.** LLM вызывается только при изменении страницы, то есть меньше 10 запросов в день даже в сезон. Любой бесплатный тариф с запасом это покрывает.

Если заданы оба ключа, используется Gemini. Чтобы выбрать Groq, создайте **переменную** (не секрет) `LLM_PROVIDER = groq`: **Settings → Secrets and variables → Actions → Variables**.
Если модель по умолчанию перестала работать (её сняли с поддержки), поменяйте `GEMINI_MODEL` или `GROQ_MODEL` в `env` шага «Run agent» в `check-sources.yml`.

### 6. Тестовый запуск агента на одном источнике

**В GitHub:** **Actions → Check sources → Run workflow**, в поле `source` укажите `mext-undergrad` и нажмите **Run workflow**.
В логе шага «Run agent» должно появиться примерно следующее:
```
[mext-undergrad] 2221 символов, sha256=65da06cc534e…
[mext-undergrad] подтверждено цитатами: …
Готово: источников 1, ошибок 0, уведомлений N
```
Первый запуск создаёт «первый снимок страницы» и предложения для пустых полей. Они появятся в журнале приложения со статусом «требует проверки», а в Telegram придёт сообщение. Если запустить ещё раз, будет `без изменений` и LLM не вызовется. Чтобы принудительно вызвать LLM, отметьте `force`.

**Локально** (Python 3.10+):
```bash
pip install -r agent/requirements.txt
```
```bash
python agent/check_sources.py --source mext-undergrad --dry-run
```
`--dry-run` ничего не записывает и не отправляет в Telegram. Без ключа LLM агент только скачивает страницу и считает хеш. С ключом (Linux/macOS: `export GEMINI_API_KEY=…`, PowerShell: `$env:GEMINI_API_KEY="…"`) он покажет, какие поля подтверждены цитатами.

Проверить напоминания на любую дату:
```bash
python agent/notify_deadlines.py --dry-run --today 2026-11-16
```
Юнит-тесты:
```bash
python -m unittest discover tests -v
```
Посмотреть приложение локально: запустите `python -m http.server 8765` и откройте http://localhost:8765.

### 7. Проверьте напоминания

**Actions → Deadline reminders → Run workflow**, `today = 2026-11-16`. Для Stipendium Hungaricum это ровно 60 дней до дедлайна, так что в Telegram должно прийти сообщение.

## Ежедневное использование

### Подтверждение изменений

В приложении откройте **Журнал → Требуют проверки**. У каждого предложения видно, что было, что стало, цитату и ссылку на источник. **Обязательно откройте ссылку и сверьте цитату сами.**

- **Без токена:** кнопка «Подтвердить» копирует ID и открывает **Actions → Review change**. Там нажмите **Run workflow**, выберите `action = approve` (или `reject`) и вставьте `change_id`.
- **С токеном (удобнее с телефона):** создайте fine-grained токен на https://github.com/settings/personal-access-tokens/new. В **Repository access** выберите *Only select repositories* и этот репозиторий, в **Permissions** выставьте *Actions: Read and write*. Вставьте токен в **Настройки** приложения. После этого кнопки сразу запускают workflow, и через ~1 минуту изменение попадает в репозиторий отдельным коммитом.
  Токен хранится только в localStorage вашего браузера. Не вводите его на чужих устройствах.

Подтверждённый дедлайн получает статус `confirmed`.

### Чек-лист документов

Отметки сразу сохраняются на устройстве. Если задан токен, каждая отметка также коммитится в `programs.json` через workflow `Review change` (`action = checklist`). Пункты чек-листа добавляются и меняются в `programs.json`.

### Добавить источник или программу

1. Добавьте URL в `official_urls` программы в `data/programs.json`.
2. Добавьте запись в `data/sources.json`:
   ```json
   { "id": "auca-admissions", "program_id": "auca", "url": "https://…/admissions", "selector": null, "enabled": true }
   ```
   Указывайте конкретную страницу с датами, а не главную: на главной часто меняются новости, и это даёт ложные срабатывания. Если на странице много «шума», задайте `selector` — CSS-селектор основного блока, например `"main"` или `"#content"`.
3. Закоммитьте изменения. Вручную можно править любые поля программы. Если вы нашли данные сами, заполните `source_url` и `quote`.

**Что агент не может проверять сам** (сайты отвечают 403 на автоматические запросы):
- сайт посольства Японии в КР (объявление MEXT);
- сайт International Ala-Too University.

Их нужно проверять вручную. Если появится другая страница с той же информацией (например, новость на сайте, который открывается), добавьте её в `sources.json`.

### Поиск новых стипендий и грантов

Агент не ищет в интернете — это осознанное ограничение. Вместо этого он следит за **страницами-каталогами** из белого списка (`kind: "catalog"`). Сейчас это портал Минобрнауки КР [student.edu.gov.kg](https://student.edu.gov.kg/): туда выкладывают все конкурсы на обучение за рубежом по межгосударственным соглашениям (Венгрия, Китай и другие).

Когда страница каталога меняется, агент просит LLM перечислить программы бакалавриата, которые на ней упомянуты. Для каждой программы нужна дословная цитата со страницы и ссылка, которая на этой странице реально есть. Дальше:
- программы, которые уже есть в трекере, и ранее отклонённые пропускаются;
- остальные попадают в журнал как «🆕 Новая программа», а в Telegram приходит уведомление;
- кнопка **«Добавить в трекер»** создаёт карточку программы и добавляет её ссылку в белый список, так что со следующего запуска агент проверяет и её. **«Не интересно»** — отклоняет, больше эта программа не предлагается.

Добавить ещё один каталог можно так:
```json
{ "id": "my-catalog", "kind": "catalog", "program_id": null, "url": "https://…/scholarships", "selector": null, "enabled": true }
```

### Установка как приложение и работа без интернета

Откройте сайт в Chrome на Android и выберите «⋮ → Установить приложение» (на iPhone в Safari: «Поделиться → На экран Домой»). Без сети откроется последняя загруженная версия, а вверху появится плашка «Нет сети — показаны сохранённые данные». Чат, подтверждения и отметки с токеном без интернета не работают. Данные (`data/*.json`) всегда сначала запрашиваются из сети. Статика берётся из кэша и обновляется в фоне, поэтому новая версия сайта подхватывается при следующем открытии. Если что-то выглядит устаревшим, закройте и снова откройте приложение.

### Календарь дедлайнов

Агент при каждом запуске пересобирает `data/deadlines.ics`; после подтверждения изменения его пересобирает и workflow «Review change». Подписка: **Настройки → Календарь дедлайнов → Скопировать адрес**, затем в Google Календаре: «Другие календари» → «＋» → «Добавить по URL». Адрес: `https://<логин>.github.io/<репозиторий>/data/deadlines.ics`. Каждое событие напоминает о себе за 7 и за 1 день. Если дата ещё не подтверждена, в названии события стоит «(ожидается)».

### Профиль → Рекомендации, Бюджет, Эссе

Всё это хранится только в браузере. В **Настройках → Резервная копия** можно скачать файл со всеми личными данными и восстановить их на другом устройстве.
- **Рекомендации.** Для каждого рекомендателя указываются статус, сроки и программы. Если до дедлайна меньше 14 дней, а письма ещё нет, на карточке программы появится предупреждение.
- **Бюджет.** Расходы указываются в KGS, USD или EUR, курс вводится вручную. Сайт показывает итоги и что нужно оплатить до конца месяца. Официальные сборы программ из `fees[]` в `programs.json` можно добавить шаблоном.
- **Эссе.** Требования к эссе берутся из `essays[]` в `programs.json` и только из официальных источников. Счётчик слов подсвечивает превышение лимита, хранятся 5 последних версий. Кнопка «Проверить в чате» просит Gemini дать советы, не переписывая текст за вас.

### Экзамены

В `data/events.json` записаны даты SAT, ОРТ, IELTS и экзаменов MEXT. Для каждого экзамена указан крайний срок регистрации и источник. На главной экраны переключаются фильтром «📝 Экзамены». Напоминания приходят за 30, 14, 7, 3 и 1 день до конца регистрации и до самого экзамена, события также попадают в календарь. Агент следит за страницей дат SAT и сообщает об изменениях, а сами даты в `events.json` правятся вручную.

### Статус заявки

На карточке программы, в блоке «Моя заявка», отмечается этап: Изучаю → Готовлю → Подано → Экзамен/интервью → Результат (приняли, отказ или лист ожидания). На главной есть фильтр «Активные», а программы с результатом уходят в конец списка. Этап хранится в браузере. Если в настройках задан токен, этап также коммитится в `programs.json` через workflow «Review change». Заметка к заявке хранится только на устройстве.

### Мой профиль (GPA, IELTS и т.д.)

Вкладка **Профиль**: средний балл, IELTS, TOEFL, Duolingo, SAT, ОРТ, JLPT, дата рождения, направления, олимпиады. Данные хранятся **только в вашем браузере**: репозиторий публичный, и оценки туда не попадают.

Если у программы в `programs.json` заданы числовые минимумы (`thresholds`), карточка показывает блок «Мои баллы vs требования» с отметками «✓ проходит» или «✕ не хватает». Сейчас минимумы есть у AUCA (IELTS, TOEFL, Duolingo) и Stipendium Hungaricum (возраст). Добавить минимум для другой программы:
```json
"thresholds": { "ielts": { "value": 6.0, "source_url": "https://…", "quote": "…" } }
```
Поддерживаются ключи `ielts`, `toefl_ibt`, `duolingo`, `sat`, `ort`, `gpa_percent`, `age_min`.

### Чат по программе

Кнопка 💬 открывает чат: на карточке программы — по этой программе, на остальных экранах — по всем сразу. Ответ строится на данных трекера, снимках официальных страниц, которые сохранил агент, и вашем профиле. Если ответа в этих данных нет, чат должен прямо сказать «в данных трекера этого нет» и подсказать, где проверить.

Как включить:
1. Получите бесплатный ключ на https://aistudio.google.com/apikey. Лучше создать **отдельный** ключ, не тот, что лежит в GitHub Secrets.
2. Откройте **Настройки → Чат-помощник** и вставьте ключ.
3. Рекомендуется ограничить ключ адресом сайта: [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → ключ → *Application restrictions → Websites* → `https://<ваш-логин>.github.io/*`.

Ключ хранится только в этом браузере, запросы идут напрямую в Google.

### Бот отвечает на команды (необязательно)

Без этого шага бот только присылает уведомления. Чтобы он ещё и отвечал на `/deadlines`, `/exams`, `/todo`, `/program mit`, `/list`, `/pending` и `/help`, разверните бесплатный Cloudflare Worker из папки `worker/`. Worker читает JSON с вашего сайта и отвечает только chat id из белого списка, LLM не использует.

1. Зарегистрируйтесь на https://dash.cloudflare.com (бесплатно) и установите Node.js LTS (https://nodejs.org).
2. Войдите в Cloudflare:
   ```bash
   cd worker
   npx wrangler login
   ```
3. Проверьте `SITE_URL` в `worker/wrangler.toml` и задайте секреты. Каждая команда спросит значение:
   ```bash
   npx wrangler secret put TELEGRAM_BOT_TOKEN
   npx wrangler secret put ALLOWED_CHAT_IDS
   npx wrangler secret put WEBHOOK_SECRET
   ```
   `ALLOWED_CHAT_IDS` — ваш chat id (несколько можно через запятую). `WEBHOOK_SECRET` — любая длинная случайная строка из латинских букв и цифр.
4. Разверните Worker:
   ```bash
   npx wrangler deploy
   ```
   Команда напечатает адрес вида `https://admission-tracker-bot.<имя>.workers.dev`.
5. Подключите webhook. Откройте в браузере ссылку, подставив свои значения:
   `https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=<АДРЕС_WORKER>&secret_token=<WEBHOOK_SECRET>`
   Должен прийти ответ `"ok":true`.
6. Чтобы команды появились в меню бота, отправьте @BotFather `/setcommands`, выберите бота и вставьте:
   ```
   deadlines - ближайшие дедлайны
   exams - экзамены и регистрация
   todo - неготовые документы
   program - кратко о программе (id)
   list - все программы
   pending - что ждёт проверки
   help - справка
   ```

Бесплатного плана Cloudflare (100 000 запросов в день) хватит с огромным запасом. Отключить webhook: `https://api.telegram.org/bot<ТОКЕН>/deleteWebhook`.

### Кто ещё может пользоваться

- **Сайт** открывается по ссылке у всех, кому вы её дадите. Чек-листы, профиль, ключ и токен у каждого свои: они хранятся в его браузере. Подтверждать изменения может только тот, у кого есть доступ к репозиторию или токен.
- **Telegram-бот** пишет только в те чаты, которые указаны в секрете `TELEGRAM_CHAT_ID`. Посторонний может найти бота и нажать Start, но ничего не получит: бот не отвечает на сообщения. Чтобы добавить, например, родителя или учителя:
  1. этот человек нажимает Start у вашего бота;
  2. вы находите его id через `getUpdates` (как в шаге 4 настройки);
  3. в секрете пишете id через запятую: `5295630219,123456789`.

  Можно и группой: добавьте бота в группу и укажите id группы (он начинается с `-`).
- **Токен бота** никому не давайте: с ним можно писать от имени бота.

## Статусы

| Статус | Значение |
|---|---|
| 🟢 `confirmed` — подтверждён | Дата взята с официальной страницы (с цитатой) и проверена вами |
| 🟡 `expected` — ожидается | Предположение по прошлым годам, официального объявления ещё нет |
| ⚪ `unknown` — не проверено | Даты нет |
| 🟣 требует проверки | Агент нашёл новое значение, ждёт вашего решения |
| 🔴 ошибка источника | Страница не открылась (Telegram сообщит после 3 неудачных проверок подряд) |

## Расписание

| Workflow | Когда |
|---|---|
| Check sources | февраль–октябрь: по понедельникам в 12:00 по Бишкеку; ноябрь–январь: каждый день в 12:00 |
| Deadline reminders | каждый день в 09:00 по Бишкеку. Напоминание приходит, если до дедлайна осталось 60, 30, 14, 7 или 1 день (дни считаются по Бишкеку) |

GitHub может запускать cron с опозданием на 5–30 минут. В публичных репозиториях без активности 60 дней расписание автоматически отключается. Агент регулярно делает коммиты, так что обычно это не грозит; если всё же случилось, включите workflow заново во вкладке Actions.

## Ограничения

- Страницы, которые рисуются JavaScript-ом (SPA) или требуют входа, отдают мало текста. Например, на `apply.stipendiumhungaricum.hu` агент увидит в основном оболочку. PDF агент не читает: добавляйте HTML-страницу, на которой лежит ссылка на PDF.
- LLM может ошибиться в интерпретации даже с верной цитатой. Поэтому изменения применяются только после вашего подтверждения.
- Чек-листы в `programs.json` типовые. Сверьте их с официальными объявлениями, когда они выйдут.
